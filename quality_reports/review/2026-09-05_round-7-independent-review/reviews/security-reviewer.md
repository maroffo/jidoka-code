## Drain and stop (M1) supplementary checks
- Between `beginDrain` and the runtime `paused = true` (`ProductionEngineJobRuntime.swift:500-509`) the actor yields at several awaits; `applyDispatchGate` running in that window calls `openAdmission()` which throws (durable `paused = 1`) and closes the gates (`:1390-1397`); `activateRollout` in that window hits `.busy` (runtime `paused` false) and would anyway collide on `active_rollout_authorization_id IS NULL` (`RolloutAuthorityStore.swift:249-255`).
- `resumeExactRecovery` requires `recoveryRequired`, an empty in-memory permit set and closed admission (`RolloutAuthorityStore.swift:582-593, 599`), and un-pauses only in the same transaction that reopens the lane (`:655-665`); the SQL trigger `app_settings_rollout_scope_required` (`DatabaseSchema.swift:3582-3620`) refuses any `paused = 0` write without a matching active lane.
- Startup with an open lane goes to `recoveryRequired` (`RolloutAuthorityStore.swift:739-749`, called from `JobCoordinator.swift:252-253`), so a crash mid-drain cannot resume silently.
